### B.5 过程中被真实执行揪出的 3 个自身缺陷（已修）

1. **永续走错主机**：`fapi` 路径被发往现货主机列表（`data-api.binance.vision` 无 `/fapi`）→ 404。修：现货/永续各自独立主机列表。
2. **`probe()` 把不可达当"已连接"**：`DataSourceTransientError` 是 `DataSourceError` 的子类，`except DataSourceError: return True` 让被墙的 OKX 显示"连接成功"。修：先捕获 transient → False。
3. **深历史分页页序颠倒**：分页按"新窗口→旧窗口"追加，却反向遍历，导致 `bars[0]` 是最旧窗口的最后一根（实盘 1500 根时"时间戳递减=False"）。修：按抓取顺序拼接、页内反转。

> 这 3 条都只有"真跑"才会暴露：单测锁定后 2 条，实盘冒烟暴露第 1 条。

### B.6 预存在失败用例的处理（10 条，非本轮引入）

**判定方法**：`git archive HEAD` 导出干净副本，用**同一个 `.venv`** 跑同一批用例 → 出现**完全相同的 10 条失败**，故与本轮改动无关。根因是**代码在演进、用例没跟上**（叠加"CI 从不跑测试"，长期无人发现）。

| 用例 | 失败原因 | 处理 |
|---|---|---|
| `test_settings_round_trip.py::test_defaults` | 断言 `reasoning_effort == "high"`，源码默认已是 `"low"`（`config/settings.py:21`；而 `config/settings.example.json` 仍写 `high` → 同时是文档漂移） | **修正断言为 `"low"`** |
| `test_market_defaults.py::test_tv_forex_auto_probe_tries_all_forex_presets` | 期望值照抄"预设列表去掉 A 股交易所"，未跟随后来新增的加密交易所 | **改为行为断言**（不含股票/加密交易所 + 保持预设顺序） |
| `test_json_validator.py::test_stage2_raw_sample_repair_then_parse`、`::test_strip_fences_includes_repair` | 依赖 `tools/stage2_raw_sample.txt`，该文件**从未提交**进仓库 → 任何全新克隆都必然失败 | **加 `skipif`（带原因）** |
| `test_validation_lenient_fixes.py` ×2 | 宽松归一化后的枚举值漂移（`not_triggered` vs `pending`、订单类型别名） | **`xfail(strict=False)`** + 原因指向本报告 |

> 说明：5 条行为漂移用例我**没有**直接改断言去迎合现状——那会把"可能的行为退化"固化成"期望"（例如"不下单却带入场价被判 Ok"是否属于安全性退化，需要作者判断），因此 xfail 隔离并在本报告登记；一旦行为回归，pytest 会以 **XPASS** 提示。
> 结果：受影响文件现在通过（`37 passed, 2 skipped` 与 `5 xfailed`），CI 的 pytest 步骤得以成为**可用的阻断门**而不是长期红灯。

### B.7 测试套件在无头环境的真实状态（重要）

1. **含 e2e 时无法跑完**：`tests/e2e/test_smoke_free_chat.py` 会**先失败、再挂死**（连 `--timeout=25 --timeout-method=thread` 都拦不住，卡在不可中断的 Qt/C 调用上）。**干净 HEAD 副本同样如此** → 预存在问题，与 A.3 中"worker/线程清理缺口"很可能同源（推测）。这也直接解释了为何项目 CI 一直只做 `import pa_agent` 冒烟：一旦真的 `pytest`，CI 会挂到超时。
2. **剔除 e2e 后可以跑完**，但全量仍有 **35 个失败**，集中在两类：

   - 要恢复"全量阻断"，先分诊上面 35 条：把需要外部服务的用例标记为 `live`（或加环境探测 `skipif`），把过时断言按 B.6 的方式处理。
